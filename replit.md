# AlgoDesk — Algorithmic Trading Dashboard

A full-stack institutional algorithmic trading system with a Bloomberg-terminal-inspired UI, real-time WebSocket feeds, strategy execution, risk management, backtesting, and portfolio analytics.

## Run & Operate

- `pnpm --filter @workspace/api-server run dev` — run the API server (port 8080)
- `pnpm --filter @workspace/trading-dashboard run dev` — run the React dashboard
- `pnpm run typecheck` — full typecheck across all packages
- `pnpm run build` — typecheck + build all packages
- `pnpm --filter @workspace/api-spec run codegen` — regenerate API hooks and Zod schemas from the OpenAPI spec
- `pnpm --filter @workspace/db run push` — push DB schema changes (dev only)
- Required env: `DATABASE_URL` — Postgres connection string

## Stack

- pnpm workspaces, Node.js 24, TypeScript 5.9
- API: Express 5, port 8080, proxied at `/api`
- DB: PostgreSQL + Drizzle ORM
- Validation: Zod (`zod/v4`), `drizzle-zod`
- API codegen: Orval (from OpenAPI spec)
- Build: esbuild (CJS bundle)
- Frontend: React + Vite, Tailwind CSS, Shadcn UI, Recharts, Wouter, TanStack Query

## Where things live

- `artifacts/api-server/src/` — Express API server
  - `engine/` — trading engine modules (marketData, strategies, risk, execution, sentiment, backtester, tradingEngine)
  - `routes/` — all API route handlers
  - `db/` — Drizzle schema and migrations
- `artifacts/trading-dashboard/src/` — React frontend
  - `pages/` — dashboard, trades, portfolio, analytics, strategies, risk, backtest, sentiment, notifications
  - `components/Layout.tsx` — sidebar nav + live ticker marquee
  - `hooks/use-websocket.ts` — WebSocket client that invalidates React Query cache
- `lib/api-spec/` — OpenAPI spec (source of truth for API contract)
- `lib/api-client-react/` — Generated React Query hooks (do not edit manually)
- `lib/db/` — Drizzle ORM schema

## Architecture decisions

- Contract-first API: OpenAPI spec → Orval codegen → typed React Query hooks in frontend
- Trading engine runs in-process with Express; uses `setInterval` for tick simulation
- Paper trading mode: all trades are simulated with synthetic OHLCV data (GBM process)
- WebSocket broadcasts at `/api/ws` for real-time position/risk/sentiment updates
- Risk engine hard stops at daily loss limit, max drawdown, exposure cap; kill switch closes all positions
- Sentiment adjusts position sizing multiplier (0.5× – 1.5×) based on institutional/retail/momentum signals

## Product

- **Dashboard**: Live engine status, portfolio metrics, open positions table, recent alerts
- **Trade Journal**: Paginated trade history with filters, P&L calendar heatmap, trade detail panel with notes/tags
- **Portfolio**: Equity curve vs benchmark, drawdown chart, allocation pie, correlation matrix heatmap, positions table
- **Analytics**: 12 performance metrics (Sharpe, Sortino, Calmar, win rate, expectancy, etc.), time breakdown bar chart, strategy comparison
- **Strategies**: Toggle on/off, edit risk %, symbols, and strategy parameters inline
- **Risk Engine**: Live risk score gauge, daily loss/drawdown/exposure gauges with breach indicators, settings form, emergency kill switch (with confirmation dialog)
- **Backtester**: Run simulations with walk-forward and Monte Carlo options; results include equity curve, trade list, Monte Carlo fan chart
- **Sentiment Engine**: SVG circular gauges for institutional/retail/momentum/composite; mode selector; custom weight sliders
- **Alerts**: Alert feed with severity badges (critical/warning/info), notification threshold settings

## Gotchas

- All API routes mount with `/api` prefix — never call service ports directly; use `localhost:80/api/...`
- `lib/api-client-react/src/generated/` files are REGENERATED by codegen — never manually edit
- Trading engine auto-starts in paper mode when server starts (see `tradingEngine.ts`)
- WebSocket reconnects automatically with 3s backoff
- Dark mode is forced by `document.documentElement.classList.add("dark")` in App.tsx
